# RUN2구룡포 — 완주 다음의 여행

서울에서 기차로 온 10km 러너가 완주 후 구룡포에 들렀다가 포항역으로 돌아오는 **로컬 실행 데모**입니다. 최신 [여정 기획](docs/run2-guryongpo-hackathon-journey.md)과 [사용자 동작·API 명세](docs/run2-guryongpo-atomic-spec.md)를 기준으로 만들었습니다.

## 실행

Node.js 22.12 이상이 필요합니다.

```sh
npm install
npm run dev
```

터미널에 표시되는 URL을 엽니다. 포트는 `PORT` → `CONDUCTOR_PORT` → `5173` 순서로 선택하며, localhost에만 바인딩합니다.

```sh
npm test          # 명세의 D01–D08, 진행 상태, 관측 장애, Agent 검증
npm run build    # TypeScript 검사 + 프로덕션 빌드
npm start        # 빌드 결과를 같은 Express 서버로 제공
```

## 3분 시연

1. **내 하루 만들기**: 도착 시각·18:30 귀가 열차를 저장합니다.
2. **내 하루**: 구룡포 후보를 담고, 도착 → 준비 체크 → 출발 → 완주를 진행합니다. `시연: 완주 직후로 이동`으로 건너뛸 수도 있습니다.
3. **완주 후 확인**: 조금 지쳤어요 / 30분 이내 / 10:40 준비 완료를 선택합니다.
4. **구룡포 코스**: 점심·거리·카페, 16:20 역 도착, 목표까지 100분 여유를 확인합니다.
5. 도우미에 **“16시 기차로 바꿨어”** → **이 변경 적용하기**. 카페가 빠지고 거리 구경이 5분으로 줄어 역 도착이 15:15로 바뀝니다.
6. **데모 컨트롤 → 혼잡만 82%로**. 사용자 조건을 그대로 유지하면서 거리 구경도 빠지고, 교통 여유 20분을 더한 계획상 역 도착은 15:30이 됩니다.
7. **이 코스로 갈게요** → 길찾기 → 구룡포 도착 확인 → 장소 완료·건너뛰기·추가 휴식 → 포항역 복귀 → 도착 확인까지 진행합니다.

데모 컨트롤에서 기본, 조기 귀가, 혼잡, 대기, 출발 지연, 경로 누락, 오래된 관측을 반복 시연할 수 있습니다. `처음부터 다시 시작`은 이 브라우저의 데모 상태만 초기화합니다.

## 구현 범위와 정직한 연결 상태

| 구분                  | 현재 동작                                                                                               |
| --------------------- | ------------------------------------------------------------------------------------------------------- |
| 사용자 화면           | S1–S5, 모바일 대응, 장소 상세, 수정·비교 패널                                                           |
| 결정 엔진             | 시간·보행·관측 신선도·의료 우선·경로 유효 시간대 검증, 단계별 남은 일정 계산                            |
| 자연어                | 키 없으면 명시된 시연 요청 파서. 키 설정 시 OpenAI Responses의 실제 함수 호출 루프                      |
| OpenAI 응답           | 요청 해석·4개 도구 선택은 모델, 화면의 시간·이유는 결정 엔진의 정형 출력. 자유문장 생성은 사용하지 않음 |
| E-UM 교통·대기        | 서버 HTTP 어댑터와 실제 연결 증거 패널. 키 누락·401·timeout·응답 누락을 성공과 구분                     |
| 지역 관측의 결정 효과 | **시연 관측**으로 재계산. E-UM 실응답은 단위·시간·대표 범위 검증 전까지 별도 표시                       |
| 버스·보행             | 가정한 고정 스냅샷. 실제 운행편·정류장·운영일 미검증                                                    |
| 지도                  | 방문 순서 개념도 + 카카오맵 목적지 링크. 도로 경로나 실시간 교통 지도 아님                              |
| 택시                  | 비교 UI, 미확인 비용·시간 표시. Kakao Mobility 미연결로 선택 비활성화                                   |
| 식당·카페             | 구룡포시장·가옥거리 권역의 자리표시자. 상호·영업시간·메뉴 미확정                                        |
| 저장                  | 브라우저 localStorage에 현재 계획·진행 저장. 서버 DB·로그인·서버 세션 API는 범위 밖                     |
| 분석                  | 별도 관광 전환 이벤트 수집 없음. 도착은 사용자 수동 확인                                                |

**API 키가 없는 상태에서 실제 E-UM / OpenAI 연결 성공을 주장하지 않습니다.** 해커톤의 실호출 요건 충족은 별도 키·장비 설정과 응답 검증이 필요합니다. 모든 경로와 일정은 `executionMode=DEMO`입니다.

## 선택적 실제 API 연결

`.env.example`을 `.env`로 복사해 로컬에서 설정한 뒤 서버를 다시 실행합니다. 키는 브라우저로 보내지 않습니다.

| 변수                  | 용도                                                              |
| --------------------- | ----------------------------------------------------------------- |
| `OPENAI_API_KEY`      | OpenAI API 키                                                     |
| `OPENAI_MODEL`        | 함수 호출을 지원하는 계정의 모델. 기본 `gpt-4.1-mini`             |
| `EUM_SERVICE_KEY`     | 주최 측에서 승인한 E-UM 서비스 키                                 |
| `EUM_AIR_DEVICE_ID`   | 확인된 구룡포 대기 장비 ID                                        |
| `EUM_MAX_AGE_SECONDS` | 공급자의 갱신 간격 확인 후 설정할 신선도 기준. 미설정이면 UNKNOWN |

OpenAI에는 현재 열차 시각·출발 준비·걷기 상한·진행 단계와 요청 문장만 전달합니다. 응답에는 `store:false`, 전체 20초 제한, 도구 실행 최대 3회, 모델 응답 최대 4회를 적용합니다. 상태가 불편하거나 입력 문장에서 불편 증상이 감지되면 관광 요청을 멈추고 상태 확인 화면으로 돌아갑니다. 질문·비교는 일정을 변경하지 않으며, 변경 도구도 미리보기만 반환합니다.

E-UM 엔드포인트는 저장소 명세를 따릅니다. 실제 응답 계약은 아직 미검증입니다. `hour`에 시각만 있거나 시간대가 없으면 오늘 날짜를 임의로 붙이지 않습니다. 원본 응답 중 허용한 필드만 반환하며 인증 키·요청 URL·프롬프트는 로그에 남기지 않습니다.

## 구조

```text
src/             React 화면·반응형 스타일·방문 순서 지도
shared/model.ts  Zod 입력 계약·장소 데이터·시간 변환
shared/planner.ts 순수 결정 엔진 (클라이언트와 서버에서 공유)
server/          Express + OpenAI 함수 호출 + E-UM HTTP 어댑터
tests/           명세 기반 계산·장애·Agent 테스트
public/images/   시연용 지역 사진
docs/            기존 기획·제출 문서 (변경 없음)
```

`POST /api/plan`, `POST /api/agent`, `GET /api/status`, `GET /api/evidence`를 제공합니다. 이 데모는 서버 상태를 보관하지 않습니다. 계획 변경마다 revision을 올리고, 변경 전 요청의 늦은 응답은 화면에서 폐기합니다. 더 쉰 시간은 도착·완료 시 소비되어 중복 가산되지 않습니다.

시연 버스 스냅샷은 출발 10:00–12:00, 복귀 출발 12:00–18:00 범위에 한정합니다. 버스 요금·배차는 만들지 않습니다. 시연 정책은 혼잡 50/75%에서 추가 여유 10/20분, PM2.5 50 이상이면 선택적 야외 구경 제외, 열차 30분 전 역 도착 목표입니다. **공인 교통·건강 기준이 아닙니다.**

계획은 마지막 사용 후 7일이 지나면 다음 접속에서 초기화합니다. 채팅 원문·상세 이동 이력은 저장하지 않습니다. 실제 서비스로 공개하려면 서버 세션 소유권·요청 제한, 검증된 양방향 경로·장소, 실관측 정규화, Kakao Mobility·TourAPI, 분석 동의 정책이 추가로 필요합니다.
