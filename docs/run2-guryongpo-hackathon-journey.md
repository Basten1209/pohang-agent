# RUN2구룡포 해커톤: 서울에서 기차로 온 러너 한 명의 하루

> **완주 후 구룡포에서 밥 먹고 잠깐 구경한 뒤, 서울행 기차 시간에 맞춰 돌아오는 계획을 만들어 준다.**

작성일: 2026-10-06. 기존 기획서를 바탕으로 새로 제안하는 **화면·사용자 여정 중심의 축소안**이다. 구현 완료 명세가 아니며, 기존 제출 DOCX/PDF는 이 내용으로 수정하지 않았다.

**확정된 현지 이동 원칙:** 버스를 기본으로 안내하고, 시간·피로 때문에 필요하면 사용자가 비용을 확인한 뒤 택시를 선택한다.

**멘토 피드백 반영 상세본:** [사용자 동작·AI Agent·외부 API 명세](run2-guryongpo-atomic-spec.md)에 29개 동작의 상황·입력·출력·외부 호출·실패 처리와 해커톤 요건 대응을 정리했다. E-UM 교통·대기 2종과 OpenAI 상호작용을 필수 구현 기준으로 삼는다.

## 1. 이번 데모에서 증명할 것

사용자는 마라톤에 참가하려고 포항에 왔다. 구룡포 방문은 아직 결정하지 않았다. 서비스의 과제는 이 사람이 **“멀고 피곤할 것 같으니 바로 돌아가자”에서 “이 정도면 들렀다 갈 수 있겠다”로 결정하도록 돕는 것**이다.

이를 위해 대회 전에는 하루 동선과 구룡포 방문 후보를 저장하고, 완주 후에는 실제 출발 가능 시각·걷고 싶은 정도·귀가 열차를 반영해 그 계획을 수정한다. 추천 결과에는 반드시 **가는 방법, 현지에서 할 일, 포항역으로 돌아오는 방법**이 함께 있어야 한다.

데모의 중심은 사용자 요청과 구룡포 관측이 같은 계획을 바꾸는 두 장면이다.

> “18:30 서울행 기차를 타는 러너에게 구룡포 식사·골목 구경·카페 코스를 제시한다. 사용자가 귀가 시각을 앞당기면, 같은 화면에서 카페를 빼고 구경을 줄여 복귀 계획까지 다시 계산한다.”

이어 같은 귀가 조건에서 구룡포 혼잡 입력만 변경해 추가 축소를 보여준다. 실제 E-UM 호출 증거와 시연용 관측 변경은 구분한다. 자연어 요청에는 OpenAI Agent가 필요한 조회·계산 도구를 호출하고 변경 이유를 설명한다.

기존 문서에서 가져올 것은 계획 저장, 완주 후 확인, 시간 계산, 지역 데이터, 재계획이다. 이번에는 경기 중 페이스 관리, 가족·크루, 호미곶, 자유로운 여행 검색을 제외한다.

**가정의 경계:** 사용자 요청의 ‘마라톤 참가’를 기존 기획의 10km 종목으로 구체화했다. 아침 대회에 맞춘 당일 첫차 도착을 전제하지 않도록 전날 도착으로 잡았다. 대회명·개최일·출발시각과 아래 열차 시각은 실제 행사나 운행편을 특정하지 않는 시연 설정이다. 숙소·열차는 이미 사용자가 예약한 것으로 두며 앱에서 예약하지 않는다.

짐을 숙소에 남긴 경우에는 완주 후 `짐을 찾고 출발할게요`로 준비 완료 시각·출발지를 바꾼다. 이 데모는 **관광 전에 짐을 회수**하는 방식으로 제한한다. 구룡포 방문 후 숙소를 재방문하는 복잡한 동선이나 보관소 예약은 다루지 않는다.

## 3. 전체 사용자 여정

화면은 **S1 계획 입력 / S2 내 하루 / S3 완주 후 확인 / S4 구룡포 코스 / S5 다음 행동**의 5개다. S2는 시간대와 사용자의 확인에 따라 내용만 달라진다. 관광지 설명과 이동 상세는 S4·S5의 하단 패널로 연다.

| 단계 | 사용자의 생각 | 보여줄 화면과 정보 | 사용자 상호작용 | 앱의 반응·관광 전환 역할 |
| --- | --- | --- | --- | --- |
| ① 서울, 출발 전 | “대회장까지 어떻게 가고, 끝나면 뭘 하지?” | **S1 → S2**. 참가 대회, 포항 도착 계획, 귀가 열차, 대회 전후 동선 | 행사 안내 링크를 가정한 데모 URL 접속 → 열차 시각 입력 → `내 하루 만들기` | 대회장 안내와 귀가 마감을 한곳에 저장. 구룡포를 고려할 수 있는 시간을 미리 보임 |
| ② 내려가는 기차 안 | “포항까지 가는데 점심은 괜찮은 걸 먹고 싶다.” | **S2** 하단에 구룡포 사진과 `점심 + 골목 구경 + 카페` 후보 카드 | `완주 후 후보로 담기` 또는 `나중에 정할게요` | 관광 의향만 저장. 체력·교통이 정해지기 전 방문을 확정하지 않음 |
| ③ 포항 도착 후 | “우선 숙소에 가고, 내일 집결 장소를 알아두자.” | **S2 도착 상태**. 포항역 → 입력한 숙소, 다음 날 숙소 → 집결지 안내 | `포항에 도착했어요` → `숙소 길찾기` → 다음 날 집결 위치 확인 | 낯선 지역에서 당장 필요한 이동을 도와 앱을 다시 열 이유를 만듦 |
| ④ 대회 당일, 출발 전 | “출발 장소랑 준비물만 빨리 보고 싶다.” | **S2 대회 상태**. 집결지, 출발 시각, 준비물 3개, 짐 회수 계획 | 준비 항목 체크 → `집결지 길찾기` → `출발해요` | 주 행동은 대회 준비. 구룡포 카드는 접어서 유지하고 입력을 다시 요구하지 않음 |
| ⑤ 달리는 동안 | “지금은 뛰는 데 집중하자.” | **S2 경기 중 상태**. `완주 후 다시 열어주세요`와 완주 버튼 | 앱 사용 불필요 | 실시간 GPS·페이스·알림 없이 경기 시간을 건너뜀 |
| ⑥ 완주 직후 | “배고프고 좀 지친다. 그래도 구룡포 갈 수 있나?” | **S3**. 완주 시각, 컨디션·보행 선호, 짐을 챙겨 출발 가능한 시각, 저장된 귀가 열차 | `완주했어요` → `조금 지쳤어요`·`30분 이내로 걷기` → `지금 가능한 코스 보기` | 사전 후보를 현재 시간과 조건으로 다시 계산. 이전 입력을 이어받음 |
| ⑦ 구룡포로 갈지 결정 | “어떻게 가고, 뭘 하고, 몇 시에 돌아오지?” | **S4**. 추천 한 코스, 구간별 이동, 걷는 시간, 비용 정보, 포항역 복귀 예상 | 장소 카드 보기 → 필요하면 `덜 걷기`·`귀가 시각 변경` → `이 코스로 갈게요` | 매력과 실행 가능성을 동시에 설명. 수정하면 삭제·변경된 일정과 이유가 바로 보임 |
| ⑧ 구룡포로 이동 | “지금 어느 정류장으로 가야 하지?” | **S5 이동 상태**. 승차 정류장·방향·하차 위치, 첫 목적지 | `정류장 길찾기` / `대중교통 경로 열기` → 도착 후 `구룡포에 도착했어요` | 추천에서 실제 이동 시도로 연결. 도착은 수동 확인하며 자동 추적하지 않음 |
| ⑨ 식사·관광 중 | “밥 먹었으니 조금만 구경하고 쉬고 싶다.” | **S5 체류 상태**. 다음 장소 한 곳, 짧은 설명, 남은 일정, 복귀 출발 권장 시각 | `식사 마쳤어요` → 다음 장소 길찾기. 피곤하면 `이 장소 건너뛰기`, 늦으면 `30분 더 쉬기` | 현재 시각·장소에서 남은 동선을 다시 계산. 계속 머물 수 있을 때만 다음 장소를 제안 |
| ⑩ 서울로 귀가 | “이제 역으로 가자.” | **S5 귀가 상태**. 현재 위치 → 포항역, 열차 시각, 역 도착 목표 | `포항역으로 출발` → 대중교통 경로 열기 → `역에 도착했어요` | 귀가까지 여정을 닫음. 여행 완료는 같은 화면의 완료 상태로 표시 |

**유입 전제:** 행사 안내에 실제 링크를 넣으려면 배포 협의가 필요하다. 해커톤은 행사 안내를 재현한 데모 링크에서 시작한다. 로그인·앱 설치·주최 측 제휴를 전제하지 않는다.

## 4. 화면별로 무엇을 만들 것인가

### S1. 내 하루 만들기

- 대회와 10km 종목은 데모 링크에서 미리 선택한다.
- 핵심 입력: `포항 도착 일시`, `서울행 열차 출발 일시`, `대회 후 하고 싶은 것: 식사 / 짧은 구경 / 휴식`.
- 현지 이동은 버스를 기본 선택한다. 숙소 위치와 짐 회수 여부는 보조 입력에 둔다. 숙소가 없으면 해당 경유 안내만 생략한다.
- 귀가 입력 옆에 `출발역: 포항역`을 표시해 서울 도착시각과 혼동하지 않게 한다.
- CTA: **`내 하루 만들기`**. 저장 후 S2로 이동한다.

첫 입력부터 자연어 채팅을 요구하지 않는다. 정해진 항목을 선택하고 바로 하루 계획을 보는 것이 이 사용자에게 빠르다.

### S2. 내 하루 — 대회 전 앱을 열 이유

상단에는 `지금 할 일`, 중간에는 `포항역 → 숙소 → 대회장 → 미정 → 포항역` 타임라인, 하단에는 구룡포 후보를 배치한다.

구룡포 후보 카드 예시:

> **완주 기념 점심은 구룡포에서 어때요?**
>
> 항구 근처에서 밥을 먹고, 일본인 가옥거리의 짧은 구간을 구경한 뒤 카페에서 쉬는 코스예요. 이동과 귀가 시간을 포함한 계획은 완주 후 다시 확인할게요.
>
> `[완주 후 후보로 담기]` `[나중에 정할게요]`

시연자는 단계 이동 도구로 전날→당일을 전환할 수 있다. 실제 사용자 화면은 저장된 일정과 `도착했어요`·`출발해요` 같은 확인으로 바뀐다. 열차 위치 추적, 완주 자동 감지, 백그라운드 푸시는 구현하지 않는다.

### S3. 완주 후 확인 — 새 여행 설문 없이 20초 안에

완주 시각은 버튼을 누른 현재 시각으로 채우고 수정할 수 있게 한다. 관광 계산에 필요하지 않은 구간별 기록은 받지 않는다.

1. `지금 상태는 어떤가요?` → 괜찮아요 / 조금 지쳤어요 / 몸이 안 좋아요.
2. `얼마나 걷고 싶나요?` → 15분 이내 / 30분 이내. 출발 전 선택이 있으면 유지한다.
3. `언제 출발할 수 있나요?` → 준비되었어요 / 30분 뒤 / 직접 입력. 짐 회수 시 출발지도 함께 확인한다.

하단에는 `포항역 18:30 출발`과 수정 버튼을 유지한다. `몸이 안 좋아요`를 고르면 관광 생성을 중단하고 현장 도움 안내를 보여주는 기존 기획의 분기를 유지한다. 목표 기록과 실제 기록의 차이로 건강 상태를 추정하지 않는다.

### S4. 구룡포 코스 — 데모의 중심 화면

정보 순서는 **가고 싶은 이유 → 내 조건에 맞는 이유 → 전체 동선 → 실행**이다.

| 영역 | 표시 내용 | 상호작용 |
| --- | --- | --- |
| 대표 카드 | `완주 후 구룡포 점심과 짧은 골목 구경`, 사진 1장 | 사진·장소 탭으로 관광 설명 패널 열기 |
| 적합성 요약 | 예상 걷기, 구룡포 체류, 왕복 이동, 포항역 도착 예상, 열차까지 여유 | `왜 이 코스인가요?`로 입력·데이터에 근거한 짧은 설명 |
| 동선 | 현재 출발지 → 구룡포 식사 → 가옥거리 일부 → 카페 → 포항역 | 지도와 시간표에서 같은 순서 표시. 거리와 이동시간을 따로 표시 |
| 이동 상세 | 도보·대기·승차·환승, 교통비와 식사·카페 예상 지출 | 버스 기본. `택시 비교`는 시간·요금 근거가 있을 때만 제공하고 사용자가 선택 |
| 수정 | 덜 걷기 / 카페 빼기 / 귀가 시각 변경 | 같은 카드와 경로를 갱신하고 `무엇이 왜 바뀌었는지` 표시 |
| 여행에 대한 질문·요청 | `왜 카페가 빠졌어?`, `16시 기차로 바꿨어`, `역까지 택시 타면?` | 현재 여행에 한정한 자연어 입력 → OpenAI의 도구 호출 → 설명 또는 새 코스 미리보기. 비교만으로 택시 선택을 바꾸지 않음 |
| 실행 | 저장된 코스와 최신 확인 시각 | **`이 코스로 갈게요`** → S5 |

버스비·택시비·음식값은 검증된 값만 합산한다. 모르면 `비용 확인 필요`로 표시하고 총액이 확인된 것처럼 보이지 않게 한다. 비용 때문에 택시를 거절하면 버스 조건으로 재계산한다.

관광지 패널에는 사진, 방문할 이유 두 문장, 권장 체류시간, 접근 동선·계단 여부, 운영시간 확인 상태, 일정에 포함된 이유, 길찾기를 넣는다. 후기·별점·검색·상점 예약은 만들지 않는다.

### S5. 다음 행동 — 도착해서도 쓰는 화면

상단에 현재 단계와 다음 목적지 하나, 하단에 남은 일정과 **`포항역으로 돌아가기`**를 고정한다. 구룡포행, 현지 이동, 역 복귀에 같은 화면을 사용한다.

- `도착했어요`·`마쳤어요`: 현재 장소와 시각을 갱신한다. 길찾기를 열었다는 사실만으로 도착 처리하지 않는다.
- `이 장소 건너뛰기`·`30분 더 쉬기`: 현재 장소에서 남은 이동과 역 복귀를 재계산한다.
- 재계산 후에는 `카페 제외 → 역 도착 예상 변경`을 보여 준다. 구룡포에 이미 도착한 뒤 시간이 부족하면 새 관광 추천 대신 역 복귀 경로를 우선한다.
- 앱을 다시 열면 마지막 단계로 복귀하고 시간 정보를 갱신한다. 백그라운드에서 버스나 위치를 계속 감시한다고 표현하지 않는다.
- S4와 같은 입력창에서 `30분 더 쉬고 싶어`, `지금도 이 코스로 갈 수 있어?`를 요청할 수 있다. Agent가 현재 진행과 필요한 지역 데이터를 확인한 뒤 같은 화면을 갱신한다.

## 5. 구룡포에서 제안할 경험과 이동 경로

첫 코스는 **구룡포 중심부 한 권역**으로 제한한다. 관광 경험은 식사, 거리 구경, 휴식 세 가지면 충분하다.

| 순서 | 후보와 경험 | 이 사용자에게 제안하는 이유 | 구현 전 확인 |
| --- | --- | --- | --- |
| 1 | 구룡포시장·항구 인근 식당 한 곳에서 점심 | 완주 직후의 식사 수요를 구룡포 방문 이유로 연결 | 실제 상호·좌표, 1인 식사 가능 여부, 영업일·시간, 메뉴·가격, 정류장부터 접근 |
| 2 | 구룡포 일본인 가옥거리의 짧은 구간 | 지역의 거리 풍경과 역사를 보고 사진을 남길 이유 제공 | 실제 보행 경로·경사·계단. 공원 계단을 오르는 구간은 기본안에서 제외 |
| 3 | 같은 권역의 카페 한 곳 | 오래 걷지 않고 쉬면서 지역 내 체류를 이어감 | 실제 상호·좌표, 영업시간, 가격, 접근 동선. 피로·시간에 따라 생략 |
| 4 | 현재 장소에서 포항역으로 복귀 | 구룡포에서 역까지 돌아갈 수 있어야 방문을 결정할 수 있음 | 복귀 방향 정류장, 운행편·환승·대기와 역 진입 시간 |

**큰 동선:** 포항역 → 영일대 인근 숙소 → 영일대 인근 대회장 → 짐 회수·출발 준비 → 구룡포 중심부 → 포항역. 귀가 때 대회장에 다시 돌아갈 필요가 없는 시나리오다.

구룡포 일본인 가옥거리는 포항시가 소개하는 관광지다. 관광공사 자료는 거리의 역사와 드라마 촬영지 맥락, 구룡포공원 돌계단 및 과메기문화관으로 올라가는 접근 동선을 설명한다. 따라서 **과메기문화관을 ‘실내라서 덜 걷는 장소’로 자동 대체하지 않는다.** 기본안은 공원·문화관까지 확장하지 않고, 남길 구간의 실제 보행 부담을 별도로 확인한다. [포항시 관광 안내](https://pohang.go.kr/phtour/wmap/tourInformation/view.do?tour_info_idx=347), [한국관광공사 접근 동선 안내](https://access.visitkorea.or.kr/cos/detail.do?cotId=0f18f9aa-0310-4240-b5bc-e47b583f71cb)

상호 미정인 식당·카페는 현재 기획의 자리표시자다. 해커톤 전에 각각 한 곳과 대체 후보 한 곳을 확인해야 실제 목적지가 있는 길찾기를 시연할 수 있다. 음식은 취향과 1인 식사 조건으로 선정하며 회복 효과를 주장하지 않는다.

## 6. 차 없는 사용자에게 필요한 경로 정보

기존 자가용 중심 제출본을 그대로 쓰면, 버스 대기·정류장 접근·환승이 빠진다. **서울에서 기차를 탔다는 이유로 포항 현지에서 차가 있는 것처럼 계산하지 않는다.**

| 구간 | 앱에서 안내할 것 | 이번 구현 방식 |
| --- | --- | --- |
| 포항역 → 숙소 | 실제 목적지, 대중교통 경로 열기 | 외부 지도 연결. 관광 시간 계산과 별개인 전날 이동 |
| 숙소 → 대회장 | 공식 집결 위치, 도착 목표, 짐 관련 메모 | 행사 정적 정보와 지도 연결 |
| 완주 후 출발지 → 구룡포 | 정류장까지 걷기, 승차 방향, 대기·환승, 하차 후 첫 장소까지 | 데모 구간의 사전 확인 경로를 저장하고 외부 지도와 연결 |
| 구룡포 안 | 장소 사이 실제 보행 경로, 계단·경사, 총 걷는 시간 | 소수의 사전 확인 경로. 직선거리를 보행시간으로 간주하지 않음 |
| 구룡포 → 포항역 | 복귀 방향 정류장, 대기·환승, 역까지 전체 시간 | 가는 길과 별도로 검증. 귀가 마감에서 역산 |

포항시 구룡포읍 안내에는 영일대를 지나는 900번과 포항역에서 구룡포로 가는 9000번이 소개되어 있다. 다만 이 안내만으로 행사일 양방향 운행·정류장·대기시간을 확정할 수 없다. **현재 기획에는 특정 버스의 ‘몇 분 뒤 도착’을 넣지 않는다.** [포항시 구룡포읍 교통 안내](https://pohang.go.kr/gu/contents.do?mid=0501010105)

해커톤에서 범용 대중교통 경로 엔진을 만들 필요는 없다. 정해진 출발지와 목적지에 대해 운영자가 경로 스냅샷을 등록하고, 출처·확인 시각·도보/대기/승차/환승 구성·적용 가능한 시간대를 보관한다. 사용자가 허용 시간대 밖으로 출발을 바꾸거나 현재 위치가 등록 구간을 벗어나면 이전 소요시간을 그대로 쓰지 않는다.

스냅샷의 범위 밖이거나 복귀편을 확인할 수 없으면 `경로 확인 필요`로 바꾸고 외부 지도에서 확인하도록 한다. 이때 관광 가능 판정을 확정하지 않는다. **외부 지도를 여는 것과 우리 앱이 최신 경로를 확보하는 것은 별개다.** 재조회 가능한 연동을 확보하기 전, 미확인 구간은 시연용 값으로만 보여 준다.

### 버스 기본, 필요하면 택시 선택

- 처음에는 구룡포행과 포항역 복귀 모두 버스로 계산한다.
- 버스 대기·환승 때문에 귀가 여유가 부족하거나, 사용자가 피로·걷기 부담을 표시하면 해당 구간의 `택시 비교`를 제안한다. 앱이 자동으로 이동수단을 바꾸지 않는다.
- S4 코스 화면 또는 S5 다음 행동 화면에서 버스와 택시의 전체 이동시간·걷는 시간·예상요금을 비교한다. 택시는 승차 지점까지 이동과 예상 대기도 포함하고, 확인되지 않은 항목을 임의로 채우지 않는다.
- 사용자가 `이 구간은 택시로`를 누르면 선택한 구간만 변경하고 관광 일정·총 교통비·포항역 복귀 예상을 함께 재계산한다. 따라서 구룡포행은 버스, 역 복귀는 택시로 선택할 수도 있다. S5에는 선택한 수단에 맞춰 정류장 또는 택시 승차 지점을 표시한다.
- `버스로 유지`를 누르면 버스 조건으로 일정을 줄인다. 최소 관광 코스도 불가능하면 관광을 보류하고 역 복귀를 안내한다.

택시 비교는 차량 ETA·요금 근거를 확보했을 때 제공한다. 자동차 ETA를 버스 ETA로 사용하지 않는다. 택시 호출·예약·합승 매칭은 만들지 않는다.

## 7. 숫자로 보여주는 핵심 데모

아래는 **계산과 화면 변화 시연을 위한 고정 가정값**이다. 실제 열차·버스 시간표, 확인된 이동시간·보행시간, 영업정보가 아니다. 화면에도 `시연용 일정` 표시를 유지한다.

| 항목 | 기본 시나리오 |
| --- | --- |
| 경기 | 09:00 출발, 10:10 완주 |
| 관광 출발 준비 | 휴식·짐 정리를 마친 10:40, 영일대 인근 등록 출발지 |
| 구룡포행 | 도보·대기·승차 포함 90분 → 12:10 도착 |
| 구룡포 체류 | 식사 50분 + 거리 구경 20분 + 카페 50분 + 장소 사이 이동 10분 = 130분 |
| 총 걷기 | 구룡포행 접근 5분 + 거리 구경 중 걷기 10분 + 장소 사이 이동 10분 + 복귀 접근 5분 = 30분. 거리 구경의 나머지 10분은 설명·사진을 보는 시간 |
| 복귀 시작 | 14:20 |
| 포항역 복귀 | 도보·대기·승차·환승 및 기본 이동 여유 포함 120분 → 16:20 역 도착 예상. E-UM에 따른 추가 여유는 별도이며 이 기본 예시에서는 0분 |
| 귀가 열차 | 18:30 포항역 출발, 역 도착 목표 18:00 — 탑승 준비 여유 30분은 데모 설정 |
| 남은 여유 | 역 도착 목표 18:00 − 예상 도착 16:20 = 100분 |

시간 계산은 실제 준비 완료 시각에서 시작한다. 이미 반영한 휴식·짐 회수시간을 다시 더하지 않는다. 관광 중에는 완료한 구간을 빼고 현재 장소·시각에서 계산한다.

> **필요시간 = 구룡포행 전체 이동 + 현지 체류·이동 + 포항역 복귀 전체 이동**
>
> **남은 여유 = (열차 출발 − 탑승 준비 여유) − (관광 출발 가능 시각 + 필요시간 + E-UM 기반 추가 여유)**

관광 중 걷는 양은 정류장 접근·하차 후 이동까지 모두 합산한다. 식사·카페에 앉아 있는 시간과 걷는 시간을 분리한다. 보행 선호를 넘으면 장소를 줄이거나 이동수단을 다시 선택하게 한다.

### 같은 사람의 조건을 한 번 바꾼다

사용자가 외부에서 열차를 변경했다고 가정하고 앱에서 `18:30 → 16:00`으로 귀가 시각을 수정한다. 앱이 열차를 변경·예약하는 기능은 아니다.

| 비교 | 기존 코스 유지 | 축소 후 |
| --- | --- | --- |
| 역 도착 목표 | 15:30 | 15:30 |
| 현지 체류 | 130분 | 식사 50분 + 짧은 거리 구경 5분 + 현지 이동 10분 = 65분 |
| 제외·변경 | 없음 | 카페 제외, 거리 구경 축소 |
| 예상 역 도착 | 16:20 | 15:15 |
| 남는 여유 | −50분 → 불가 | 15분 → 시연 기준상 가능 |

단축안의 걷기는 구룡포행 접근 5분 + 짧은 구경 5분 + 현지 이동 10분 + 복귀 접근 5분 = 25분으로 둔다. 이 예시는 `30분 이내로 걷기`에 맞춘 것이다. 사용자가 15분을 선택하면 이 단축안을 그대로 내보내지 않고, 보행 조건까지 만족하는 후보가 있는지 다시 확인한다.

설명 문구는 `열차가 앞당겨져 카페를 뺐어요. 점심과 짧은 구경 후 13:15에 돌아가면, 시연용 이동시간 기준 포항역 도착 예상은 15:15예요.`처럼 **입력 변화 → 일정 변화 → 복귀 변화**를 연결한다.

이 예시는 두 출발 시간대에 동일한 이동시간을 부여한 시연 데이터다. 실제 버스는 출발시각에 따라 대기·환승이 달라지므로 변경한 출발시각의 경로로 다시 계산해야 한다. 최소 식사 코스조차 불가능하면 관광을 보류하고 포항역 이동을 제안한다.

## 8. AI와 구룡포 데이터가 하는 일

AI는 **사용자의 요청을 이해하고, 필요한 조회·계산 도구를 호출해, 같은 사람의 계획을 바꾸고 이유를 설명**한다. 현재 여행에 대한 질문과 변경만 지원해 화면과 기능 범위를 유지한다.

| 담당 | 이번에 할 일 |
| --- | --- |
| 규칙·시간 계산 | 귀가 마감, 준비 완료 시각, 운영시간, 이동시간, 보행 선호로 실행 가능한 코스 결정 |
| 지역 데이터 | E-UM 교통 `INT_S07_005`·대기 `INT_S01_004` 2종을 실제 호출해 이동 여유·야외 체류 여부에 반영. 관측 시각·장비·범위를 표시 |
| OpenAI Agent | 자연어 요청 해석, 현재 계획 조회·지역 데이터 갱신·코스 재계산·교통수단 비교 도구 호출, 근거 설명. 새 장소·버스 시각·요금은 임의 생성하지 않음 |
| 사용자 | 코스 선택, 걷는 선호·귀가시각 수정, 도착·완료 확인 |

기존 문서에서 E-UM `cntPerc`는 특정 도로 ETA가 아닌 통합 혼잡 신호로 정리되어 있다. 이를 버스 도착시간으로 치환하지 않는다. 검증 후 운영자가 정한 교통 여유시간 정책의 보조 입력으로 사용하고, 적용한 여유를 시간 계산에 한 번만 반영한다. 단순히 데이터 숫자만 띄우지 말고 어떤 이동 여유·코스 변화에 쓰였는지 보여 준다.

멘토 자료를 반영해 앞선 ‘E-UM 1종 우선’ 제안을 **교통·대기 2종 필수 구현**으로 변경했다. 이는 우리 팀의 구현 기준이며, 대회의 최소 요건과는 구분한다. 실제 응답·장비·의미는 아직 이 작업에서 검증하지 않았다. 실호출 결과와 시연용 관측 변경 데이터는 구분해서 표시한다.

추천 순서는 사전 확인한 소수 코스와 규칙으로 확정한다. Agent가 요청한 변경도 보행·운영시간·역 복귀를 다시 검사한다. 대기 때문에 실내로 바꾸더라도 시간이 부족하면 관광을 취소한다. 설명 생성에 실패하면 동일한 결정을 정형 문장으로 표시하되 AI 실호출 성공으로 간주하지 않는다. 구체적인 도구·입출력·결정 우선순위는 [상세 명세](run2-guryongpo-atomic-spec.md)를 따른다.

## 9. 이번에 남길 범위와 뺄 범위

| 반드시 만들기 | 이번 해커톤에서 제외 |
| --- | --- |
| 페르소나 1명, 대회 1개, 10km 종목 | 가족·크루·하프·풀코스별 경험 |
| 화면 5개와 관광지·이동 상세 패널 | 별도 러닝 앱, 관광 검색 서비스, 운영 대시보드 |

| 완주 후 상태·준비 시각 확인 | Apple Watch·HealthKit·GPS·공식 기록 자동 연동 |
| 구룡포 중심부 기본 코스와 단축 코스 | 호미곶·포항 전역 코스, 다도시 추천 |

| E-UM 교통·대기 2종, 시간 계산, OpenAI 도구 호출·설명 | 기상·침수·수산물 시세 등 추가 API 동시 연동 |
| 귀가 시각·걷기 선호·현재 진행에 따른 재계산, 현재 여행의 자연어 질문·수정 | 주제 제한 없는 만능 여행 비서 |

택시 비교·선택 흐름도 구현 기준에 포함한다. 차량 경로·요금이 확인되어야 비교와 선택을 완료할 수 있으며, 연동 전에는 해당 부분을 미완료로 표시한다. 관광 불가·몸 상태 불편·데이터 누락은 별도 서비스나 화면을 추가하지 않고 기존 화면의 상태로 처리한다.

## 10. 3분 발표 동선

| 시간 | 시연할 행동 | 심사자가 이해할 점 |

| 0:00–0:25 | 민준 소개 → S1 계획 저장 → S2 구룡포 후보 | 기차로 온 참가자의 귀가 제약과 사전 방문 의향 |

주 시연은 정상 코스·자연어 귀가시각 변경·혼잡 입력 변경으로 구성한다. 대기 변화, 택시 비교, 관광 불가, 몸 상태 불편, API 누락은 질문 대응용으로 준비한다. 하루가 흐르는 연출과 실제 경과시간, 실제 호출과 저장된 시연 데이터는 혼동되지 않게 표시한다.

## 11. 완료 기준과 검증할 가설

### 구현 완료 기준

- 같은 저장 계획이 S1부터 S5까지 이어지고 앱을 다시 열어도 현재 단계가 남는다.
- 귀가 목적지는 대회장·주차장이 아닌 **포항역**이다. 열차 출발과 역 도착 목표를 구분한다.
- 관광지 이름만 나열하지 않고, 식당·관광 구간·카페 및 출발·복귀 구간에 실제 목적지와 지도 링크가 있다.
- 귀가 시각 변경 시 코스·이동·역 도착 예상·설명이 함께 갱신된다.
- 등록 버스 경로의 적용 시간대 밖이나 데이터 누락 때는 관광 가능을 확정하지 않는다.
- E-UM 교통·대기 2종 실제 호출·관측/조회 시각을 확인하고, 시연 입력 교체로 만든 결과는 별도 표시한다.
- OpenAI가 실제 자연어 요청을 이해해 도구를 호출하고 그 결과로 설명·코스 변경을 제공한다. 정형 설명 대체만으로 AI 구현 완료 처리하지 않는다.
- 갈 수 없는 경우 역 복귀를 제안하며 관광을 억지로 유지하지 않는다.

### 관광 활성화 가설과 측정

**식사라는 즉각적인 방문 이유 + 짧은 관광의 매력 + 귀가 계획에 대한 확신**이 구룡포로 향하는 결정을 늘릴 것이라는 가설이다. 관광지 소개를 읽었다는 사실만으로 효과를 판단하지 않는다.

| 측정 | 정의 | 해석 |
| --- | --- | --- |
| 후보 저장률 | 구룡포 후보 저장 사용자 / 후보를 본 사용자 | 방문 의향 형성 |
| 이동 시도율 | 구룡포행 길찾기 실행 사용자 / 실행 가능한 코스를 받은 사용자 | 실제 방문이 아닌 이동 시도 |
| 자기보고 도착률 | 도착을 직접 확인한 사용자 / 구룡포행 길찾기 실행 사용자 | 위치 인증 없는 자기보고 방문 |
| 현지 다음 행동 | 도착 확인 후 두 번째 장소 길찾기·완료 확인 | 한 장소에서 추가 체류로 이어지는지 탐색 |
| 포기 이유 | 시간 부족 / 걷기 부담 / 이동비 / 경로 확인 불가 | 추천 기능보다 교통·비용 자체가 장벽인지 확인 |

초기 사용자 검증에서는 5명 안팎에게 같은 하루를 보여주고, “갈 마음이 생기는지”, “지금 어디로 가야 하는지 알 수 있는지”, “왜 코스가 바뀌었는지 설명할 수 있는지”를 확인한다. 버스 이동이 길거나 택시비가 부담되어 대부분 거절한다면, 코스 문구를 다듬는 것만으로 해결할 수 없다는 결과도 받아들인다. 매출 증가와 실제 지역 관광 효과는 현장 실증 과제로 남긴다.
