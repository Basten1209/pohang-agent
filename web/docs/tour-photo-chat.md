# 관광 사진을 채팅에서 공유하기

2026-10-11 구현. 기존 장소별 커뮤니티 저장 계약을 유지하고 채팅에서 사진 선택부터 게시 결과까지 이어간다.

## 사용자 흐름

1. 관광 장소의 방문 완료를 확인한다. 귀가 여유가 있고 몸이 불편하지 않을 때 여행 친구가 사진을 남길지 제안한다.
2. 제안의 ‘사진 남기기’, 채팅 입력창의 ‘여행 사진’, 커뮤니티의 ‘여행 사진 공유하기’, 또는 ‘여기서 찍은 사진 올릴래’라는 말로 공유 카드를 연다.
3. 명시한 방문 장소는 카드에 표시한다. 장소가 불분명하면 방문 완료 목록에서 직접 고른다. ‘여기’는 마지막 방문 완료 기록을 기준으로 장소 확인을 요구하며, 실제 위치라고 단정하지 않는다.
4. 채팅을 닫지 않고 사진 선택 → 미리보기 → 한마디 → 공개 안내 → ‘사진 공유하기’를 누른다. 사진 선택·취소·카드 열기만으로는 게시하지 않는다.
5. 서버 성공 응답 뒤 공유 완료와 저장된 사진을 표시한다. ‘공유한 여행 사진 보기’는 커뮤니티로, ‘대화 계속하기’는 다음 일정 안내로 이어진다. 다시 열면 이미 게시한 사진을 읽는다.

## 유지하는 계약

- 장소별 1개 게시물, `(trip_id, place_id)` 중복 방지. 마라톤 완주 게시물은 별도로 유지.
- 방문 예정·건너뛴 장소를 방문 완료로 자동 변경하지 않는다. 미방문 요청에는 방문 완료 방법과 가능한 다음 진행 카드를 안내한다.
- 안전 게이트가 공유 요청보다 먼저 작동한다. 자동 제안은 이동 중·귀가 중·시간 부족 때 하지 않는다. 귀가를 마친 뒤 사용자가 요청하면 기존 방문 사진을 공유할 수 있다.
- 도구 `prepare_visit_photo`는 읽기만 수행한다. 명확한 사진 공유 요청은 모델 연결 없이도 같은 서버 검증으로 처리한다.
- 사진 파일은 브라우저에서 크기를 줄이고 JPEG로 다시 인코딩한다. 이미지 바이트는 `/api/community`로만 보내고 대화·모델 입력에는 넣지 않는다.
- 변경안 승인·여정 계산·E-UM 근거·방문 진행 이벤트 규칙은 유지한다.

## 검증

- 실제 하네스와 PGlite에서 방문 → 공유 요청 → 명시적 게시 → 다음 일정, 미방문 거절, 안전 우선, 귀가 후 요청을 확인한다.
- 폼 컴포넌트에서 사진 선택/취소 시 무게시, 업로드 변환, 오류 시 미리보기 보존과 재시도, 기존 게시물 복원을 확인한다.
- 전체 테스트·타입검사·빌드 및 격리 로컬 서버의 HTTP 계약을 검증하고 무료 데모에 배포한다.
- Chrome 도구 연결 불가 시 화면 검증을 완료했다고 보고하지 않는다. 실기기 설치 확인은 기존대로 사용자 범위다.
