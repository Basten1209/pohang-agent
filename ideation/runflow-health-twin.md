# RunFlow Health Twin

> 내 몸의 디지털 트윈과 구룡포의 디지털 트윈을 연결하는 AI Agent

## 1. 아이디어 한 줄 소개

마라톤 전에는 경기 준비 코치, 경기 중에는 Apple Watch 기반 페이스메이커, 완주 후에는 사용자의 회복 상태와 구룡포 디지털 트윈 데이터를 활용하는 맞춤형 관광 컨시어지로 자연스럽게 전환되는 AI Agent 앱이다.

핵심 사용자 경험은 다음과 같다.

> 경기 전에는 코치 → 경기 중에는 페이스메이커 → 완주 후에는 회복·관광 컨시어지

## 2. 배경과 문제 정의

기존 러닝 앱은 기록, 거리, 페이스, 심박수를 제공하지만 대부분 운동 종료와 함께 역할이 끝난다. 반면 관광 앱은 사용자가 방금 얼마나 강도 높은 운동을 했는지, 현재 얼마나 회복되었는지, 앞으로 어느 정도 걸을 수 있는지 알지 못한다.

또한 포항 영일대 인근에서 열리는 마라톤과 구룡포는 거리가 있어 단순히 관광지를 추천하는 것만으로는 실제 방문으로 이어지기 어렵다. 완주자는 다음 정보를 동시에 고려해야 한다.

- 현재 피로도와 불편 증상
- 남은 체류시간과 귀가 시각
- 영일대에서 구룡포까지의 교통편
- 구룡포의 기상, 대기질, 침수·월파 위험
- 관광지 운영시간과 예상 보행량

RunFlow Health Twin은 이 변수들을 대신 조합하여 먼저 `지금 구룡포에 가도 되는가`를 판단하고, 가능한 경우에만 실행 가능한 회복·관광 일정을 설계한다.

## 3. 핵심 차별점

### 3.1 두 개의 디지털 트윈 연결

- 개인 Health Twin: 과거 운동 이력, 실시간 심박·페이스, 완주 후 회복 추세
- 구룡포 Digital Twin: 기상, 대기질, 침수·월파, 방파제 보행자, 수산물 유통 정보

사용자의 몸 상태와 지역의 환경 상태를 동시에 고려해 행동을 결정한다.

### 3.2 완주 전후 맥락의 연속성

관광 단계에서 사용자가 모든 정보를 다시 입력하지 않는다. 경기 중 수집한 다음 정보가 관광 설계로 이어진다.

| 러닝 중 생성된 정보 | 완주 후 활용 |
| --- | --- |
| 실제 완주 시각 | 남은 체류시간 계산 |
| 목표 대비 기록 차이 | 회복시간 조정의 보조 지표 |
| 총 운동시간 | 관광 일정의 활동 강도 조절 |
| 심박·페이스 변화 | 개인 기준 대비 운동부하 추정 |
| 날씨 노출 | 실내·실외 코스 선택 |
| 귀가 시각 | 구룡포 방문 가능시간 계산 |
| 동반자·이동수단 | 개인·가족 일정 및 교통 설계 |

### 3.3 추천이 아닌 능동적 의사결정

일반 관광 앱이 `어디를 갈까`에 답한다면 RunFlow는 다음 행동 중 하나를 선택하고 이유를 설명한다.

- 정상 방문
- 출발 연기 및 우선 회복
- 실내 중심 코스로 변경
- 해안·방파제 구간 제외
- 짧은 식사 코스로 축소
- 방문 취소 및 귀가 권고
- 위험 증상 입력 시 관광 중단 및 의료부스 안내

## 4. 사용자 여정

### 4.1 경기 전: Race Planner

사용자는 관광 앱이 아니라 당장 필요한 러닝 도우미로 서비스를 시작한다.

입력 또는 동의 정보:

- 참가 대회와 종목
- 목표 기록
- 최근 5km·10km 기록과 평소 페이스
- Apple Health 운동 이력
- 귀가 예정 시각
- 이동수단과 동반자

Agent 기능:

- 대회 일정, 코스, 급수대, 준비물 안내
- 기상 기반 복장과 급수 계획
- 구간별 목표 페이스와 예상 완주 시각
- WorkoutKit을 활용한 운동계획 전송 또는 자체 Watch 운동 세션 준비

관광은 전면에 노출하지 않고 다음과 같이 가볍게 예고한다.

> 완주 예상 시각은 10시 12분입니다. 완주 후 컨디션이 괜찮으면 귀가 전에 가능한 포항 회복 코스를 준비할게요.

### 4.2 경기 중: Pace Copilot

달리는 동안에는 채팅보다 음성, 진동, 짧은 카드로 정보를 제공한다.

주요 데이터:

- 실시간·평균 심박수
- 현재·평균 페이스
- 이동거리와 경과시간
- GPS 위치
- 활동 에너지
- 기온, 습도, 바람 등 외부 환경

판단 예시:

- 목표보다 지나치게 빠른 페이스
- 같은 페이스에서 심박이 지속 상승
- 페이스는 저하되는데 높은 심박이 유지
- 기온·습도 상승과 함께 운동부하가 증가

안내 예시:

> 현재 목표보다 18초 빠릅니다. 다음 1km는 속도를 낮추세요.

> 평소 동일 페이스보다 운동부하가 높게 관찰됩니다. 다음 급수대 이용을 권장합니다.

### 4.3 완주 직후: Recovery Gate

완주 감지 후 바로 관광지를 추천하지 않고 회복 확인 단계를 거친다.

확인 정보:

- 완주 직후 심박수
- 완주 후 2~10분의 심박 회복 추세
- 총 운동시간과 기록 변화
- 사용자의 자가 보고 증상

간단한 상태 입력:

- 괜찮음
- 많이 지침
- 통증 있음
- 어지럽거나 메스꺼움

의학적 진단은 하지 않으며, 위험 증상이 입력되면 관광 생성을 중단하고 현장 의료진 또는 의료부스 방문을 우선 안내한다.

### 4.4 완주 후: Recovery & Trip Copilot

회복 가능한 상태일 때 구룡포 디지털 트윈과 공공데이터를 조회한다.

- 구룡포 대기질과 기상
- 침수·월파 위험
- 방파제 보행자 이동·혼잡 정보
- 수산물 유통·시세
- 관광지 위치와 운영시간
- 버스 및 귀가 정보

결과 예시:

> 예상보다 운동시간이 길었고 현재 피로도가 높습니다. 해안 산책은 제외하고, 11시 40분 버스로 이동해 실내 휴식과 식사를 중심으로 2시간 코스를 구성했습니다.

> 현재 컨디션은 양호하지만 구룡포 방파제의 해안 위험도가 높습니다. 방파제 대신 일본인 가옥거리와 과메기문화관을 연결하는 내륙 코스로 변경했습니다.

> 지금 구룡포를 방문하면 예정된 열차 탑승 여유가 부족합니다. 오늘은 방문을 권장하지 않고 다음 포항 방문용 코스를 저장하겠습니다.

## 5. 맞춤형 관광 설계

| 사용자·환경 상태 | Agent 행동 |
| --- | --- |
| 회복이 빠르고 시간이 충분함 | 해안 산책 + 문화관광 + 회복식 |
| 피로도가 높음 | 보행거리 축소, 실내·식사 중심 |
| 하체 통증을 입력함 | 계단과 장거리 보행 제외 |
| 월파·강풍 위험이 높음 | 방파제·해안 구간 제거 |
| 버스 출발이 임박함 | 즉시 이동과 다음 편의 일정을 비교 |
| 귀가시간이 촉박함 | 관광지 수 축소 또는 방문 취소 |
| 어지럼증·메스꺼움을 입력함 | 관광 중단, 의료지원 안내 |

## 6. 데이터 구성

### 6.1 마라톤 단계

마라톤 장소는 구룡포 디지털 트윈의 공간 범위 밖이므로 다음 데이터를 활용한다.

- Apple Watch HealthKit 운동 데이터
- 사용자 GPS와 대회 코스
- 대회 운영정보 및 공지
- 기상청 실황·단기예보

### 6.2 구룡포 단계

대회 제공 데이터/API를 최소 1개 이상 실제 호출한다.

- 대기오염 환경분석·예측
- 구룡포항 침수·월파 예측
- 방파제 보행자 이동 예측·안전경보
- 해양환경 분석
- 수산물 유통·시세

보조 데이터로 한국관광공사 TourAPI의 관광지·행사·숙박·위치 정보와 포항시 버스 데이터를 활용한다.

## 7. Apple Watch 및 HealthKit 활용

### 7.1 기술 구조

- watchOS 운동 앱
- iPhone 동반 앱
- AI Agent 백엔드
- 구룡포 디지털 트윈·공공데이터 API
- 지도 기반 일정 인터페이스

Apple Watch는 한 번에 하나의 운동 세션만 실행할 수 있으므로, 실시간 페이스 안내를 위해서는 RunFlow Watch 앱이 `HKWorkoutSession`을 직접 실행하는 구조가 적합하다.

### 7.2 최소 활용 지표

해커톤 MVP에서는 다음 네 가지에 집중한다.

- 실시간 심박수
- 현재 페이스
- 이동거리
- 완주 후 심박 회복 추세

### 7.3 개인정보 보호

HealthKit 데이터는 사용자 동의 후 필요한 항목만 읽는다. 상세 원본은 가능한 한 기기에 보관하고 서버에는 다음과 같은 파생 상태만 전달한다.

```text
exertionLevel: high
recoveryState: delayed
walkingCapacity: low
```

상세 심박 이력, 전체 HealthKit 기록, 수면 원본, 불필요한 GPS 이력은 서버에 저장하지 않는 것을 원칙으로 한다.

## 8. 시장성과 정책적 타당성

직접적인 `마라톤 참가자 → 구룡포 방문 전환율`은 공개 자료로 확인하기 어렵다. 대신 이미 운영되는 정책·시장 패턴을 결합한다.

### 8.1 참고할 선행 패턴

- 제주국제관광마라톤: 마라톤과 해안 관광, 셔틀을 결합한 스포츠 관광 축제
- 제주 런트립 상품: 항공 + 숙박 + 참가권 + 대회장 이동 + 러닝 콘텐츠 결합
- 소노 런트립: 숙박 + 러닝 + 지역 관광 콘텐츠 결합
- 경주 벚꽃마라톤: 스포츠 관심사를 활용한 외지·외국인 관광객 유치
- 포항 시티투어: 영일대 + 구룡포 + 호미곶을 연결하는 체류형 관광 노선

RunFlow는 검증된 런트립 모델을 그대로 복제하지 않고, 고정형 일정의 한계를 디지털 트윈과 AI Agent로 보완한다.

| 기존 방식 | RunFlow |
| --- | --- |
| 모든 참가자에게 동일 일정 | 개인별 운동·회복 상태 기반 일정 |
| 사전 예약형 고정 코스 | 완주 후 실시간으로 생성·변경 |
| 기상정보 표시 | 위험에 따라 행동과 동선을 변경 |
| 장소 추천 | 방문 가능 여부부터 판단 |
| 러닝과 관광 데이터 분리 | 하나의 사용자 맥락으로 연결 |

### 8.2 확보된 간접 근거

- 포항 해안권에서는 회당 약 1만 명 규모의 마라톤 행사가 개최된다.
- 외지 참가자와 가족 동반 참가 사례가 확인된다.
- 실제 대회에서 탈진, 근육 경련, 발목 염좌 등에 대한 의료지원 수요가 존재한다.
- 영일대 대형 행사 방문객이 구룡포와 호미곶을 함께 방문한 선례가 있다.
- 포항시는 영일대와 구룡포를 시티투어로 연결하고 있다.
- 9000번 버스가 영일대와 구룡포를 연결하지만 안내된 배차 간격은 약 44분이다.
- 제주에서는 런트립이 지역 경험과 소비로 이어지는 관광 흐름으로 관찰되고 있다.

## 9. AI Agent의 역할

RunFlow는 단순 질의응답을 넘어 다음 작업을 연속적으로 수행한다.

1. 과거 운동 기록과 환경을 분석한다.
2. 개인별 레이스 계획을 생성한다.
3. 경기 중 심박·페이스 변화에 따라 계획을 수정한다.
4. 완주와 사용자 상태 전환을 감지한다.
5. 회복 상태를 비의료적으로 분류한다.
6. 구룡포 디지털 트윈 API를 호출한다.
7. 방문 여부와 이동·회복·관광 순서를 결정한다.
8. 환경이나 귀가 조건이 바뀌면 일정을 다시 계획한다.

## 10. 해커톤 MVP

### 10.1 구현 범위

1. 목표 기록과 과거 러닝 정보 입력
2. Apple Watch에서 심박·페이스·거리 수집
3. 운동부하에 따른 페이스 조정 안내
4. 완주 감지와 회복 상태 확인
5. 구룡포 디지털 트윈 API 실제 호출
6. 회복·교통·관광 일정 생성
7. 위험 변화에 따른 일정 재계획

### 10.2 데모 시나리오 A: 정상 회복

- 심박과 페이스가 안정적임
- 완주 후 회복 추세가 양호함
- 구룡포 환경이 양호함
- 해안 산책, 문화관광, 회복식 일정 생성

### 10.3 데모 시나리오 B: 높은 운동부하 또는 환경 위험

- 경기 중 심박 상승과 페이스 저하 발생
- Agent가 감속과 급수를 안내함
- 완주 후 회복이 지연됨
- 구룡포 강풍·월파 위험도 상승
- 해안 코스를 제거하거나 관광을 연기·취소함

해커톤에서는 실제 지역경제 성과보다 `서로 다른 사용자·환경 조건에서 Agent의 결정이 합리적으로 달라지는가`를 검증한다.

## 11. 안전 및 표현 원칙

RunFlow는 의료기기나 진단 서비스가 아니다. 사용자에게 안전을 보증하지 않으며, 증상 입력 시 현장 의료지원 이용을 우선 안내한다.

피해야 할 표현:

- 심장 이상 감지
- 탈수 진단
- 안전한 상태 보증
- 의료적 관광 가능 판정

권장 표현:

- 개인 기준 대비 운동부하가 높게 관찰됨
- 회복이 평소보다 지연되는 경향
- 휴식 또는 의료부스 방문 권고
- 현재 조건에서 관광을 추천하지 않음

## 12. 기대효과와 확장성

### 사용자

- 준비, 레이스, 회복, 관광을 하나의 흐름으로 이용
- 컨디션과 환경을 고려한 실행 가능한 일정 제공
- 위험한 상황에서 무리한 관광을 예방

### 포항시·구룡포

- 대규모 스포츠 행사 방문객을 구룡포 체류와 소비로 연결
- 포항시가 추진하는 영일대–구룡포 관광 동선의 개인화
- 익명화된 수요 정보를 활용한 셔틀·관광 운영 개선 가능

### 확장

- 걷기대회, 트레일러닝, 자전거대회 등으로 확대
- 불꽃축제 등 영일대 대형 행사 방문객에게 적용
- 포항 외 다른 지역의 스포츠 관광 모델로 이전

## 13. 핵심 메시지

### 프로젝트 설명

> 기존 러닝 앱은 완주와 함께 역할이 끝나고, 기존 관광 앱은 사용자의 운동 상태를 알지 못한다. RunFlow Health Twin은 Apple Watch로 수집한 사용자 동의 기반 운동 데이터를 경기 중 페이스 조정에 활용하고, 완주 후에는 이를 회복 상태와 적정 활동량으로 변환한다. 이후 구룡포 디지털 트윈의 환경·안전정보와 결합해 방문 여부부터 판단하고, 가능한 경우에만 개인별 회복여행을 설계한다.

### 한 줄 카피

> 기록을 관리하던 AI가 완주와 동시에 회복과 여행을 관리하는 AI로 전환된다.
